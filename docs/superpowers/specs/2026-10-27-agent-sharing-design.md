# 专家与团队混合共享设计

## 目标

专家和团队的所有者可以把资源共享给多个指定用户、多个用户角色，或所有用户，并允许这些范围混合生效。已有 `is_shared=true` 的资源继续表示“共享所有人”。

## 方案

在现有 `agents.is_shared` 之外增加共享目标表 `agent_share_targets`：

- `agent_id`：引用 `agents.agent_id`；
- `target_type`：`user` 或 `role`；
- `target_id`：用户 ID 或 `user_role_id`；
- 唯一约束 `(agent_id, target_type, target_id)`，避免重复目标。

`agents.is_shared=1` 表示所有人可访问；当它为 0 时，访问者必须是所有者、管理员，或命中共享目标表中的用户/角色。已有共享资源不回填目标表，保持全员共享语义。

## API

专家与团队创建、更新接口增加：

- `shared_user_ids: list[int]`；
- `shared_role_ids: list[str]`；
- `is_shared: bool` 继续代表是否所有人共享。

更新时只要共享字段出现在请求中，就以请求值替换该资源的完整共享配置；未出现则保持原配置。返回资源时附带 `shared_user_ids` 和 `shared_role_ids`，方便编辑表单回显。共享目标只允许所有者或管理员修改，并校验用户、角色存在。

## 前端

专家和团队编辑表单共用共享配置控件：一个“所有人”开关、用户多选、角色多选。关闭“所有人”后仍可提交用户和角色组合；至少存在一种目标时允许保存。列表和现有共享展示逻辑继续使用后端返回的 `is_shared`/访问结果。

## 兼容与边界

- 迁移不改变已有 `is_shared` 数据；已有共享专家/团队仍对所有非禁用用户可见。
- 删除或撤销共享时，关联目标同步清理。
- 所有者和管理员不受共享目标限制。
- 目标用户或角色被删除后，访问判定自然失效；更新时不接受不存在的目标。

## 验证

- 后端单元测试覆盖共享判定、用户目标、角色目标、混合目标和全员兼容行为。
- API 集成测试覆盖专家与团队创建/更新、越权修改、目标回显及访问范围。
- 前端测试覆盖用户/角色多选和“所有人”开关提交 payload。
- 运行相关测试，最后执行 `make all`。
